# 블록 젤리 흔들림 — 결과 정의 (2026-10-11, ten-step-loop 스킬 6회차)

기준선(before): 블록은 고정, 수면만 파인다(WAVESIM.md). 패널은 물 색만(`stepp1/panel.png`).
요청: "바다 아래쪽 모래 쪽 잡고 흔들면 젤리 흔든 것처럼 흔들리기". 레퍼런스 `aquamodel.mov` 0~1.75s(`.visual-check/ref-shake/sheet.png`, `big02/05/08/11.png`).

## 레퍼런스 분석
- 잡고 끌면 **블록 전체가 강체로 기운다**(섬·야자수·방갈로·바닥 그림자가 같이 움직인다, 모서리는 직선 유지 = 전단이 아니라 회전). 기울기 최대 ≈ 8~10°, 놓으면 2~3번 되튀며(언더댐핑) ≈ 1.5s 안에 멈춘다.
- 기우는 동안 **물은 수평을 지키려 반대쪽으로 쏠린다**: 앞면 물결선이 비스듬해지고(big05), 큰 파면 하나가 수면을 가로질러 벽에 부딪혀 되돌아온다(big02 오른쪽 능선, 이후 전체 울렁임).
- "젤리" 느낌은 되튐(오버슈트)과 블록 윗부분이 아랫부분보다 살짝 늦게 따라오는 데서 온다.

## 설계 결정 (묻지 않고 고른 기본값)
- 블록(지층·모래·물·소품·생물)을 한 그룹에 넣고 **가운데 높이를 피벗으로 회전**(x·z 축 2자유도). 잡은 손의 화면 이동 → 월드 xz 변위 d → 목표 기울기 θ = (d × up)·k (바닥이 손을 따라가고 윗부분이 반대로). 감쇠 스프링(ω ≈ 2π·1.8Hz, ζ ≈ 0.14)으로 따라가고, 놓으면 0 으로 되튄다. 최대 0.07rad(≈ 4°) — 수심 2.8 블록에서 가장자리 수위차 ±0.5 안.
- 물의 수평 유지: 수면 정점 셰이더에 **수평 보정항** L = −θz·x + θx·z 를 더하고(기운 블록 안에서 수평), 기울기 **변화량**만큼 반대 부호의 선형 기울기를 시뮬에 넣는다(순간엔 물이 못 따라오므로) → 쏠림 파가 생겨 벽에 반사. 물 옆면 윗띠는 수면 높이를 따라 내려가 틈·유리띠가 안 생기게 한다.
- 젤리 보조 흔들림: 각속도에 비례한 작은 전단(윗부분 지연)을 회전 위에 얹는다. 과하면 모서리가 휘어 레퍼런스와 멀어지므로 상한을 둔다.
- 입력: 지층·모래(섬 포함) 메시 pointerdown 으로 시작, 이동·놓기는 window 에서 받는다(빠르게 흔들면 포인터가 메시를 벗어남). 잡는 동안 수면 파기(hover/drag)는 끈다. `?tilt=x,z` 는 정적 기울기 캡처용.

## 단계별 기록
1. 그룹 두 겹(바깥: 피벗 높이로 올려 회전, 안쪽: 되돌림 + 전단 행렬)으로 블록을 묶었다. 조명·오버레이는 바깥에 둔다. `?tilt=x,z` 정적 캡처가 가장 빨리 틀을 잡아 준다.
2. 캡처 diff 로는 되튐 횟수를 못 센다(생물 이동 3.8% 가 바닥) → `__aquaDebug.jelly` 를 50ms 로 샘플링하는 `jelly.mjs`. 첫 감도(0.0007rad/px)는 빠른 플릭에 0.03 밖에 안 나와 0.0012 로 올렸다(스프링이 손을 따라가므로 플릭은 목표의 절반쯤 도달).
3. 옆면 윗띠를 0.6 만 따라가게 하면 앞모서리가 두꺼운 입술처럼 늘어난다 → 1.4 smoothstep. 모래·지층은 따라가지 않는다(수평 보정은 물만).
4. **쏠림 1차는 기울기 변화량을 전체 선형 기울기로 주입** → 진폭이 클램프(±0.6)를 넘고, 파속 2.5u/s 라 기울기가 12초 주기 정상파로 남아 수 초 동안 수면이 기운 채였다(`dbg-sheet.png` 양쪽 포화). 레퍼런스처럼 **밀린 벽에 쌓이는 둔덕**(sign·exp, 폭 2.2, 세기 1.2)으로 바꿔 해결. `half` 는 GLSL 예약어 — 셰이더가 통째로 죽고 오버레이가 회색이 된다.
5. 전단은 각속도 비례(0.025, 상한 0.03)로 두고 12/s 로 평활. 1% 수준이라 보조 효과로만 둔다 — 더 키우면 모서리가 휘어 레퍼런스(강체)와 멀어진다.
6. 잡는 동안 수면 위를 지나가면 `onSurfaceMove` 가 buttons=1 로 드래그 골을 팠다 → grabbing 이면 리턴.
7. 모바일 flow 의 흔들기 좌표(620,750)는 390 폭에선 수면 밖이지만 블록 안이라 괜찮다. 모바일 전용 캡처는 `DRAG=150,470,260,470,140,470`.
8. 보트가 블록 고정이라 수평 보정과 어긋남(△) — 다음 루프: 보트 y 에 `uLevel` 보정을 더하면 된다.
9. 그룹 회전은 draws/tris 에 영향 없음. GPU +0.6ms 는 같은 기기 편차 범위(w0 6.4 → w9 5.13 → j9 5.71).

## 후속 (2026-10-11, 같은 날): "흔들 때는 파도 물리 무시, 그냥 젤리·푸딩 흔든 것처럼"
사용자 요청으로 **물 수평 보정(uLevel)·벽 둔덕 쏠림(uTilt)·옆면 윗띠 추종을 모두 제거**하고, 흔들림을 강체 기울기 중심에서 **푸딩 전단 중심**으로 바꿨다(레퍼런스의 액체 쏠림은 더 이상 목표가 아니다).
- 입력은 그대로(지층·모래 pointerdown → window move/up). 손 변위 d → 바닥은 +d 의 0.004/px(최대 0.6)만큼 빠르게 따라가고, 윗부분은 관성으로 −d 쪽 전단(0.0022/px, 최대 0.26 = 윗면 변위 ≈ 1.1)을 목표로 언더댐핑 스프링(2.0Hz, ζ 0.085). 전단²×1.2 의 스쿼시(눌리면 옆으로 퍼짐)와 전단에 딸린 작은 기울기(0.22)를 얹는다. 물은 블록과 함께 움직일 뿐이다.
- 수치(`jelly.mjs`, 140px 플릭): 놓은 뒤 sx −0.137 → +0.120 → −0.081 → +0.065 → −0.054 → +0.037 … 2Hz 로 대여섯 번 출렁이고 2.4s 에 0.002. 오버레이는 흔든 뒤에도 완전 평평(maxdev 0) = 쏠림 파 없음.
- 캡처: `stepj11/shear-sheet.png`(`?shear=0.2,0` / `0,0.2` 정적 전단 — 윗부분이 물째로 밀린 푸딩), `stepj11/shake-sheet.png`(30/150/300/500/800ms 좌우 출렁임 + 스쿼시). flow 데스크톱·모바일 OK. 계측 sea 60.1fps · draws 83(시뮬 스텝 1~2 편차) · tris 동일 · GPU 5.29ms · 첫 긴 작업 117ms · 에러 0.
- 결과표의 G3·G4(물 수평·쏠림 파)는 이 후속으로 **의도적으로 폐기**, G8 의 보트 △ 도 수면이 블록과 함께 움직이므로 해소. `?tilt=` 는 `?shear=` 로 바뀌었다.
