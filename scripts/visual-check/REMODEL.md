# 거북 재모델 · 크기 비례 · 입 제거 + 플러시 디테일 — 결과 정의 (2026-10-11, ten-step-loop 스킬 4회차)

기준선(before): 5종(귀상어·만타·바다거북·돌고래·고래상어) 완성 상태. 품질 기준 = `.visual-check/stepit15/matrix/sheet.png`(25케이스), 수조 = `.visual-check/stepgate16/sea.png`.
sea draws 81 · tris 348k · GPU 중앙값 ≈ 2.3ms(DPR 2) · studio draws 11 · tris 38k.

요청 세 가지:
1. 거북이 가오리처럼 보인다 → 거북답게 재모델 (현재: 등딱지가 납작·넓고, 앞지느러미가 등딱지와 같은 평면에서 날개처럼 크게 뻗음, 머리가 작음).
2. 고래상어가 너무 작다 → 5종 크기를 실제 비율에 "어느 정도" 비례하게. (실제: 고래상어 10m · 귀상어 3.5m · 만타 폭 4.5m · 돌고래 2.7m · 바다거북 1.1m)
3. 모든 종의 입 제거 → 대신 인형(플러시) 느낌을 줄 디테일을 고민해서 추가.

## 설계 결정 (묻지 않고 고른 기본값)
- **크기 비례는 수조에서 강하게, 스튜디오에서는 약하게.** 수조는 5마리가 같이 보이므로 비율이 바로 읽히고, 스튜디오는 한 마리씩이라 "화면에 잘 보이는 크기"가 우선. 실제 비율(고래상어 3.7 : 귀상어 1.3 : 돌고래 1 : 만타 폭 1.7 : 거북 0.4)을 수조에선 ≈ 2.3 : 1.25 : 1 : 1.6 : 0.65 로 압축(가장 큰 것이 수조에 갇히지 않고, 가장 작은 것이 화면에서 사라지지 않게). 스튜디오는 whale > shark ≈ manta > dolphin > turtle 순서만 지키고 전부 프레임 안.
- **플러시 디테일**은 "봉제 인형이 인형임을 드러내는 곳" 세 가지로 정했다: (a) **등 가운데 솔기**(천 두 장이 만나는 점선 박음질 — 셰이더, 드로우 0 추가), (b) **케어 태그**(배 솔기 근처 꼬리 쪽에 삐죽 나온 작은 천 라벨 + 붉은 줄 — 부품 병합이라 드로우 0 추가), (c) 거북 **콧구멍 스티치 2개**(입 없는 얼굴에 부리임을 알리는 최소 표시). 얼굴은 구슬 눈 + 볼터치만 남겨 요즘 플러시(입 없는 얼굴)처럼 깔끔하게. 상어의 mouth 옵션(타입·코드)도 지운다.

## 단계
1. 입 제거(5종 부품 + 상어 mouth 타입·코드) → tsc/lint → 매트릭스 캡처 → G5
2. 거북 SDF v2(돔·테두리·배딱지 단차·큰 머리·좁은 노 지느러미·뒷지느러미·꼬리) → `pnpm bake:turtle` → 4방향 시트 → G1
3. 거북 다듬기(3 LOD, 눈·볼 앵커, 갑판 무늬 범위) + 유영 마스크 재조정 → diff → G2, G3
4. 등 솔기 셰이더(5종) → top 뷰 5장 + 픽셀 확인 → G6
5. 케어 태그 + 거북 콧구멍 → 기본 뷰 5장 → G7
6. 스튜디오 배율 → 5종 스튜디오 캡처(가장 큰 종 프레임 안) → G4(스튜디오)
7. 수조 배율 + 분리·여유 파라미터(상어 포함) → 4프레임 + 소크 → G4(수조), G8 일부
8. 통합 점검: 매트릭스 25, 모바일, flow → G8
9. 성능 계측(sea / studio) → G9
10. 정리: README·결과표·메모리, 다른 종 해시 불변 확인 → G10

## 단계별 기록
1. 입 제거: `MouthStyle`·`mouthStyle`·`mouthPoints`·`mouthParts`·`stitchLine` 삭제(상어 11 + 거북 7 + 만타 7 + 돌고래 13 + 고래상어 15 캡슐이 사라져 tris 도 준다). 기본 뷰 5장(`stepr1/sheet.png`)으로 확인. 이전 저장값에 mouthStyle 이 있어도 `fixed` 병합이라 무시된다.
2. 거북 v2(`stepr2`): 돔 top 0.52→0.64, 폭 0.9→0.8, 테두리 띠(rim 0.09)를 돔보다 넓게 + 배딱지를 안쪽으로 들여 챙 단차. 머리 0.24→0.33, 목 굵게, 앞지느러미 폭 0.55→0.44·길이 1.36→1.0·쓸림 50°→32°·y −0.03→−0.12(테두리 아래)·끝 처짐. 첫 캡처부터 거북으로 읽혔다. 미달: 지느러미가 얇은 판(두께 0.08)이고 아랫면이 배 색이라 어색, 전체 폭이 등딱지 1.72배로 목표 경계.
3. 지느러미 두께 0.095→0.12, `part` 에서 지느러미를 털 색 전용으로(양면 같은 천), 길이 1.08→1.0 → 전체 폭 1.67배. 유영 마스크는 **등딱지 타원 바깥(outer)** 에서만 걸리게 바꿔 테두리가 함께 흔들리지 않게 했다(이전엔 |z| 0.75 부터라 테두리 0.9 까지 움직였다). diff(`stepr3/swim-diff.png`)는 지느러미 4 + 머리 끄덕임만. mid/lo 구멍 없음.
4. 등 솔기: 프래그먼트에 `topSeam = (1 − smoothstep(0, 0.03, |z|)) · smoothstep(0.2, 0.55, n.y) · (1 − bellyMask)` 점선. 고래상어는 격자선·능선과 겹쳐 옅지만 픽셀로 확인(가운데 열 191/199/204 vs 옆 91/116/136). 거북은 등딱지 가운데 열을 지나는 솔기가 육각 무늬와 자연스럽게 겹친다.
5. 케어 태그 1차는 "솔기 면(앞뒤 축 × 법선)" 에 세웠더니 옆에서 날 끝으로만 보였다 → 몸에 눕혀(면 법선 = 표면 법선) 꼬리 쪽으로 늘어뜨리고 끝을 0.5rad 들어 올림, 크기 0.17→0.24. 돌고래·고래상어는 앵커가 배 밑(법선 ↓)이라 또 날 끝 → 옆구리(y −0.02)로 올렸다. 거북 콧구멍 2 는 front 뷰에서 확인.
6. 스튜디오 배율은 "순서만" 바꿨다(고래상어 0.64→0.78, 거북 0.82→0.6). 고래상어 몸길이 3.8 이 화면 폭(≈11.1)의 34% 라 자유 유영에서도 프레임 안. 거북은 작아졌지만 머리가 커져 식별은 더 잘 된다.
7. 수조 배율: 몸이 길어진 고래상어(반 길이 1.3)·만타가 벽에 닿으면 코·날개가 유리를 뚫을 수 있어 `NavParams.inset`(벽 여유, 고래상어 0.8·만타 0.4)을 추가하고 클램프·벽 판정에서 뺐다. 분리 반경은 모두 +0.4, 상어 분리 1.6→2.2, 고래상어 lookahead 3.2/1.6·margin 1.2. 고래상어 섭식 수심을 −0.6→−0.7 로 내려 등지느러미 끝(+0.81)이 수면을 살짝만 가르게. 소크 60s problems 0.
8. 매트릭스·flow·모바일 모두 한 번에 통과. 매트릭스는 `check:render` 와 겹치지 않게 먼저 돌렸다.
9. 첫 계측 GPU 6.64ms 가 목표(3.5)의 두 배라 놀랐지만, 목표 수치가 QUALITY.md(다른 세션)에서 온 것이고 같은 기기의 직전 게이트(gate16 5.83 · it15 8.35)와 비교하면 같은 범위였다. 2회차 5.37ms. **성능 목표는 같은 기기·같은 날의 직전 게이트 값으로 잡아야 한다** — 다음 루프의 함정.
10. 다른 4종은 베이크하지 않았으므로 메시 해시 불변(타임스탬프로 확인). `next build` 는 dev 서버(3000)가 `.next` 를 쓰는 중이라 생략.
