# 수면 파임(높이장 시뮬레이션) — 결과 정의 (2026-10-11, ten-step-loop 스킬 5회차)

기준선(before): `.visual-check/stepw0/sheet.png`(idle / click / drag). 클릭·드래그하면 해석적 링 함수(`uRipples[24]`, sin(r·10.5 − age·7))가
가는 빛줄기 선 몇 개를 그릴 뿐 수면은 거의 평평하다. 요청: "파장을 만드는 형태 말고 물이 **파이게**" — 레퍼런스 `aquamodel.mov`
(29프레임 `.visual-check/ref-aquamodel/sheet.png`, 키프레임 `k1..k4-crop.png`).

## 레퍼런스 분석 (aquamodel.mov 4.8s, 1042×584, 120fps)
- 커서가 지나간 자리에 **넓고 부드러운 골(bowl)** 이 파이고, 그 테두리가 마루로 솟아 바깥으로 번진다. 링이 아니라 **면이 변형**된다(수면 실루엣이 울렁이고 아래 장면이 크게 휜다).
- 파임은 수조 **벽에 부딪혀 되돌아오고** 서로 간섭한다 → 2~3초 뒤엔 수면 전체가 불규칙한 그물 무늬로 울렁인다(k2·k3). 해석적 링으로는 못 만든다 = **2D 파동 방정식 높이장 시뮬레이션**(핑퐁 텍스처)이 필요하다.
- 마루는 희게(거품·하이라이트), 골은 짙게. 아래 커스틱/굴절이 기울기를 따라 크게 비틀린다.
- 손을 떼면 4~5초에 걸쳐 잦아들고(k4) 잔물결만 남는다.

## 설계 결정 (묻지 않고 고른 기본값)
- 시뮬레이션: RGBA half-float 렌더타깃 2장 핑퐁, 해상도 256×208(수조 15×12 비례, 셀 ≈ 0.058). R=높이, G=속도. `v += c·(이웃평균 − h); v *= damp; h += v` 를 고정 스텝(120Hz, 프레임당 최대 3스텝)으로 돌린다. 경계는 클램프 샘플링(= 반사벽).
- 입력: 프레임마다 임펄스 최대 8개 uniform(uv, 반지름, 세기). **누르거나 끌면 깊게**(−), 그냥 지나가도(hover) 살짝 파인다(레퍼런스는 클릭 없이도 변형되는 것으로 보임 — 기본값, 문서에 적는다). 드래그 궤적은 직전 점과 보간해 끊김 없이 판다.
- 수면 정점 셰이더는 24-링 루프×3 대신 텍스처 5탭(중앙+4이웃)으로 높이·법선을 얻는다 → 정점 비용은 오히려 준다. 기본 잔물결(baseWave)은 유지.
- 돌고래 점프·먹이·상어 nom 의 `addRipple` 은 같은 임펄스 API 로(점프는 솟음 +, 먹이는 작은 −).
- `calm` 슬라이더 = 감쇠, `wave` = 기본 잔물결 그대로.

## 단계
1. 시뮬 모듈(`waterSim.ts`: 타깃 2장·스텝 셰이더·임펄스 큐·고정 스텝) + `?simdebug` 오버레이 → G1
2. 수면 셰이더 통합(텍스처 높이·법선, 링 코드 제거) + 클릭 → G2
3. 포인터 입력(누름·드래그 보간·hover) → G3
4. 벽 반사·간섭 시간차 캡처, 전파 속도·반지름 조정 → G4
5. 외형(마루/골 음영·굴절 세기·하이라이트) 레퍼런스 대조 → G5
6. 감쇠·안정성(calm 연동, 소크, NaN 가드) → G6
7. 생물 연동(점프·먹이·nom) + flow → G7
8. 모바일·워밍업·리사이즈 → G8
9. 성능 계측 → G9
10. 정리·문서·결과표 → G10

## 단계별 기록
1. 시뮬 모듈·오버레이는 한 번에 됐다. 오버레이 메시는 불투명이면 투명 패스(물 옆면)가 위에 덮으므로 `transparent: true` + renderOrder 로 맨 끝에 그린다.
2. 첫 통합(`stepw1`)은 거의 안 보였다: 150Hz·c 1.0 이면 파속 ≈ 4.4u/s 라 반지름 0.55 그릇이 0.13s 만에 흩어진다. 90Hz·c 0.9(≈2.5u/s)로 늦추고 반지름 0.9·깊이 0.3 으로 키우니 면이 파였다. **파속·그릇 크기·수명은 한 묶음** — 하나만 키우면 안 보인다.
3. 드래그 골이 좁고(0.6) 굴절 0.11 이면 아래 생물이 줄무늬로 늘어진다(`stepw2b/drag-zoom.png`) → 골 0.85·굴절 0.08. hover 는 이벤트당 이동거리가 작아 `min(1, dist·4)` 로는 −0.003 밖에 안 됐다 → −0.025·dist·6.
4. 벽 반사는 클램프 샘플링만으로 자동. 첫 캡처 좌표(430,560)가 수면이 아니라 옆면에 떨어져 오버레이가 통째로 회색이었다 — 클릭 좌표는 idle 캡처에서 먼저 확인할 것.
5. 높이(vR) 기준 흰 채움은 되튐 마루가 넓어 우유빛 구름이 됐다 → 곡률(라플라시안 varying `vLap`)로 가는 마루선, 비탈 흰색은 slope 0.5 이상 0.1 만. 넓은 광택 pow16 은 0.05.
6. **수위 드리프트 두 번**: (a) 누름을 음수 임펄스 반복으로 하면 파동식이 평균을 보존해 수조 전체가 가라앉는다 → 임펄스를 부피 중립 멕시칸햇으로. (b) 지속 그릇을 위해 "손가락 제약"(h → 목표 깊이)으로 바꾸자 흘러드는 물을 계속 빨아들이는 싱크가 돼 또 내려갔다 → 타깃에 밉맵을 켜고 1×1 레벨(`texture2DLodEXT(…, 12.0)`)의 평균을 매 스텝 0.08 씩 빼서 수위를 0 에 묶는다. 오버레이 PIL 통계는 (28,50)-(518,352) 로 잘라야 한다 — 바깥 5px 의 종이색이 섞이면 maxdev 106 이 항상 나온다.
7. 돌고래 점프 물보라는 `addSplash` 가 `-0.12·strength` 였을 때 안 보였다 → `-0.25·strength`, 반지름 0.35+0.3·strength.
8. 모바일은 flow.mjs 의 드래그 좌표가 수면 밖이라 따로 `DRAG=110,410,300,370,150,440` 로 찍었다.
9. 정점 셰이더의 24-링 루프×3 이 빠져 GPU 중앙값이 6.4 → 5.13ms 로 줄었다. 시뮬 스텝은 +1 draw.
10. 같은 `stepw*` 접두사를 이전 세션이 쓴 흔적(stepw7 에 matrix·panel.png)이 있다 — 결과표는 파일명으로 가리킨다.
