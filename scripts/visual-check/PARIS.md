# 파리 전시 — 목표·단계·결과 (ten-step-loop 14회차, 2026-11-14)

- 기준선: 전시는 라군(`/lagoon`)·마리나베이(`/marina-bay`)·삿포로(`/sapporo`)·전주(`/jeonju`). 파리 없음.

- 목표 그림(품질 기준): `.visual-check/paris/target-night.png`(주) · `target-day.png` · `target-closeups.png`(낮 근접 8장). 재현용 목업 `target-mockup.html`(`?t=day`, `?focus=eiffel|sacrecoeur|louvre|notredame|arc|moulin|cafe|bridge`). 목업 경계 검사 = 블록 밖 0.

## 단계별 기록
### 1회차 (단계 1~4) — 라우트·블록·센강·랜드마크·거리
- 구조는 전주와 같다: `layout`(센강 윤곽·`inSeine`·시테섬·`riverFrame`·자리) · `parts`(재질 + 오스만 파사드·망사르드·나무·가로등, 정점색 `tint`, 강 방향 `acrossRiver`/`alongRiver`) · `ground`(블록·센강·섬·난간·잔디·큰길·바토무슈) · `landmarks`(에펠·회전목마·사크레쾨르·물랭루주·루브르·콩코르드·개선문·노트르담·다리) · `town`(오스만 2·카페·가로수·메트로·모리스·월리스·부키니스트·가로등·나무·빛 웅덩이) · `sky` · `ParisScene`(스펙). 메인 목록 `places.ts` 에 한 줄.
- 목업에서 이미 잡은 함정을 처음부터 반영: 격자 알파 텍스처는 uv 가 0..1 밖이라 **RepeatWrapping 이 없으면 가장자리 흰 줄이 늘어나 면이 꽉 막힌다**(에펠이 판처럼 보였던 원인). 다리 회전은 `atan2(-tg.x, -tg.y)` (로컬 x ⟂ 흐름) — 목업 1차는 강을 따라 놓였다. 달 판의 투명 부분이 깊이를 쓰면 달무리를 네모로 가린다.
- 카페는 오스만 건물 큰길 쪽(−x) 이면 카메라에서 안 보인다 → 센강 쪽(+z) 1층으로.
- 바토무슈 두 척은 선체(정점색) + 선실(밤 발광) 인스턴스 2드로우로 센강을 왕복, 시테섬 부근은 북쪽 갈래로 비켜 간다. 회전목마 윗부분·풍차 날개는 `bakeGroups` 로 그 안에서 병합해 돌린다.
- 캡처 `steppa1/h21.png`·`h13.png`·`closeups.png`: 배치·근접 8장 목표와 같은 요소. 미달 두 가지 수정: ① 알렉상드르 3세교 아치 옆판이 상판 밑에 숨어 안 보임 → 아치를 0.13 더 늘어뜨리고 바깥 두 장을 상판 가장자리 밖(z ±0.37~0.4)으로 (`bridge3c.png`) ② 밤 몽마르트르 언덕이 거의 검정 → 밤 재질색 `#5a6a62` → `#8a9a86`.

### 2회차 (단계 5~7) — 하루 주기·병합·목표 대비
- 하루 주기·블룸·병합은 공용 셸. 밤 전용: 초승달·달무리·별·빛 웅덩이·회전목마 전구·카페 탁자 등·개선문 불꽃·에펠 반짝임(점 4 무리, 셸 `nightOnly` 대신 tick 에서 밤 정도 × 깜빡임으로 직접 투명도). 낮 전용: 구름. 해 질 녘 `steppa2/h18.5.png` 보간 정상.
- 계측 1(dev, DPR2, 같은 세션): draws **180(밤)/154(낮)** ≤ 200, GPU 중앙값 6.94 / 5.32ms (전주 9.56 / 5.30ms), 60fps. 처음부터 예산 안 — 전주 때 배운 것(색만 다른 부품은 정점색 재질, 움직이는 그룹은 `bakeGroups`, 배는 인스턴스)을 처음부터 적용한 덕. 콘솔 404 8개 = 아직 없는 포스터 사진(단계 10 에서 생성).
- 통계(블록 영역 170,60–1230,880): 밤 목표 (128,125,149) σ73.9 / 실제 (122,120,145) σ73.9, 낮 (208,207,199) σ30.3 / (206,205,196) σ33.7. `cmp-night.png`·`cmp-day.png` 배치 같음.
- 컨펌 때 적은 세 가지: ① 다리 아치 — 1회차에 해결 ② 개선문이 첫 오스만 건물에 가림 → 개선문·에투알을 (6.8, −4.5) → (6.3, −4.75) 로, 교차로 도로가 `SITES.arc` 를 따르게 (`arc-move-c.png`) ③ 노트르담 탑 — 루버 창 둘·난간·모서리 첨두 4, 왕의 회랑 띠, 버트레스 위 작은 첨두를 더함.

### 3회차 (단계 8~10) — 조작·움직임·성능·정리
- 움직임(`steppa3/anim-a|b`, 밤 1.5초 간격 픽셀 차이): 회전목마 6.06% · 풍차 3.81% · 센강(바토무슈) 0.39% · 에펠 0.28% (`eiffel-ab.png` 에서 반짝 점이 바뀐 것 확인). 벚꽃잎은 서풍으로 비스듬히 흩날린다.
- 조작은 공용 셸(`inSeine` — 강 윤곽 안이고 시테섬 타원 밖). 파문 `ripple-crop.png` (클릭 640,578, 그 영역 1.21% 변화, 동심원 링 보임), 흔들기 `shake.png` 6.19%.
- 모바일 세로 `mobile-s.png`: 블록 전체가 화면 안. `check:flow` OK (패널 없음·에러 0).
- 메인 목록: `places.ts` 한 줄 + `pnpm posters http://localhost:3007 paris` → `public/posters/paris-day|night.webp` (전주 사진과 같은 모양, `posters-cmp.png`). 사진이 생기니 콘솔 404 사라짐.
- 공용 코드(`components/diorama/*`)는 건드리지 않았다 — 바뀐 공용 파일은 `ClientOnly.tsx`·`places.ts` 의 추가 줄뿐이라 다른 전시 렌더는 그대로 (같은 세션 전주 draws 160 = 이전 기록과 같음).
