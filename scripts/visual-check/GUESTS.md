# 리조트 손님 커플 10단계 — 결과 정의 (2026-10-11)

기준선(before): `/sea` 라군엔 사람이 없다 — 섬·방갈로·선베드·보트·해먹이 전부 빈 채로 놓여 있다. 계측(`stepn15`, M4 Pro · 1440×900 · DPR 2, 개발 서버): 60fps · draws 95 · tris 397k · GPU 중앙값 3.7ms(p95 6.5).
요청: "커플 한 쌍이 섬·방갈로·바다·배 등에서 알아서 활동하며 놀게 사람 2명을 추가. 배도 탈 수 있고, 나머지는 알아서 생각해서 다 구현."
품질 기준 캡처: `.visual-check/stepn15/h12.png`(한낮 전체), 리조트 소품의 디오라마 톤(연한 유목·코랄·흰색)을 사람도 따른다.

## 설계 결정 (기본값 — 묻지 않고 정함)
- 사람 = 플러시 인형 톤의 작은 목각 인형 2개(키 ≈ 0.32, 방갈로 0.45 · 선베드 0.46 · 보트 1.0 에 맞춘 토이 비율). 얼굴은 생물과 같은 규칙 — 구슬 눈 + 볼터치, 입 없음. 한 사람은 밀짚모자 + 민트 수영복, 한 사람은 코랄 반바지 + 짙은 머리.
- 한 사람 = 지오메트리 1개(정점 색, 부위 속성 `aPart`) + `MeshStandardMaterial` onBeforeCompile 로 부위별 회전(머리·팔 2·다리 2·몸)을 정점 셰이더에서 — 사람당 1 드로우(두 패스 2).
- 활동(커플이 항상 같이): 산책(손잡고 해변) · 선베드 눕기 · 해먹 · 얕은 물 수영 · 보트 타기(피어에서 승선 → 열린 물 순항 → 귀항) · 방갈로 테라스 데크체어 · 피어 끝에 앉아 노을 보기 · 밤 횃불 옆 앉기 · 밤엔 잠깐 방갈로 안(보이지 않음, 창 불빛).
- 시간대가 활동 가중치를 정한다(라군 시각 = `dayCycle.dayHour`): 낮 수영·선베드·보트, 노을 피어, 밤 횃불·테라스·별 보는 보트. `?guest=<활동>` 으로 고정, `?focus=guests` 근접 뷰(점검용). 상태는 `window.__aquaDebug.guests`(키 이름에 Nav 를 붙이지 않는다 — 소크의 "20초 정지" 판정은 생물용).
- 길: 섬 모래는 격자(0.2) A* + 직선 당기기, 데크는 척추선·다리 그래프, 둘은 척추선 시작점에서 만난다. 물 위는 걷지 않는다(모래 높이 > 수면 + 0.03). 야자수·덤불·파라솔 기둥·횃불은 장애물.
- 보트 1척을 정적 병합에서 빼 피어 끝에 매어 두고 움직인다(정점 색 1 드로우). 순항은 `blocked(x, TOP−0.3, z, 0.8, 0.6)` 로 섬·산호·방갈로를 피하고 벽 안쪽 1.0 여유. 선미에서 0.3초마다 수면 시뮬에 작은 파임 → 항적.

## 단계별 기록
1. 인형(`stepg1`): 정점 색 + `aPart` 지오메트리 1개, `MeshStandardMaterial.onBeforeCompile` 로 `uRot[6]`(mat3) 부위 회전 — `beginnormal_vertex` 에서 부위 번호·행렬을 잡고 `begin_vertex` 에서 피벗 기준 회전(머리·팔은 몸 회전을 겹쳐). 첫 캡처는 등만 보여 포즈 시트용 `?guest=pose:` 는 카메라를 마주 보게(yaw −0.96).
2. 포즈(`stepg2/sheet.png`): 걷기·서기·앉기·눕기·수영·손 흔들기·둥둥 7개. 걷기 0.25초 차 diff bbox > 0. 수영은 모래에서 찍으면 머리가 땅에 박힌다(물에서는 brain 이 발 높이를 TOP−0.12 로 둔다).
3. 길찾기(`stepg3`): **함정 1** 장애물 반지름을 넉넉히(사람 둘 여유 0.2) 잡고 격자 0.15 로 하니 섬이 6조각으로 끊겨 A* 가 실패 → 직선 fallback 이 물·야자수를 가로질렀다(소크 52건). 반지름을 실제 + 0.12, 격자 0.1 로 → 본섬 1조각(761칸)+곶 1조각. 실패 시 fallback 은 "닿을 수 있는 칸 중 목표에 가장 가까운 곳까지" 로. **함정 2** `randomSandSpot` 의 마지막 fallback 자리가 물이었다(선베드 앞 +0.6) → 횃불 옆으로. **함정 3** 직선 당기기의 끝점 여유(0.5)가 시작점 근처 야자수까지 무시했다 → 끝점이 *들어 있는* 장애물만 무시. 따라가는 b 는 손 옆자리가 장애물이면 a 뒤에 바짝 붙는다. 결과: `check:guestnav` 200 경로 bad 0, 브라우저 소크 60s problems 0, 손 간격 0.10~0.27(평균 0.23).
   근접 뷰(`?focus=guests`)는 야자수 관 안에 카메라가 들어가거나 위에서 잎에 가려서 세 번 바꿨다 → 잎을 숨기고(점검용) 앙각 50°·r 6.
4~7. 자리(`stepg7/sheet.png`): 선베드 2 눕기(발 쪽 +0.1, 기울임 1.2 rad, 들어올림 0.13) · 해먹 눕기(처진 가운데 높이) + 옆 모래에 앉기 · 횃불 옆 앉기(밤) · 입수→수영(발 TOP−0.12, 머리 수면 위)→둥둥(paddle, TOP−0.27)→퇴수 · 피어 끝 승선(1.2초 glide)→출항(리조트 사각형 밖 HARBOUR_GATE 를 거쳐)→순항(`blocked` 전방 탐지 + pushAway)→귀항→접안(정박 자세 뒤 1.2 에서 lerp)→하선 · 방갈로 테라스 데크체어(앞 다리가 테라스로 들어오는 집 0~3 만) · 밤엔 문 앞에서 사라졌다(22~40초) 나온다 · 노을 피어 끝 앉기. 보트는 Resort 정적 병합에서 한 척을 빼 정점 색 1 메시로.
8. 하루 스케줄(`stepg8`): 활동 가중치 표(시간대 함수)·같은 활동 연속 금지로 시작했는데 밤 소크가 보트↔방갈로만 번갈아 했다 → 바로 전 두 활동을 제외. **함정**: 소크가 도는 동안 소스를 고치면 Fast Refresh 가 `Guests` 를 다시 마운트해 커플이 시작 자리로 리셋된다 — 시작 자리가 물(선베드 앞 +0.55)이라 "물에서 걸어 나오는" 가짜 문제 20건이 찍혔다(두 소크에서 좌표가 똑같아 알아챔). 시작 자리는 횃불 옆 모래로, 소크 중엔 편집 금지. 입수 지점도 선베드 앞 +0.6 이 이미 물이라 목표가 물이었다 → `sandPath` 는 목표가 물이면 가장 가까운 칸에서 멈추고, 입수 지점은 수영 지점에서 섬 중심 쪽으로 올라오며 찾는다. 점검 키는 `guests`(소크의 `*Nav` 갇힘 판정과 분리). probe.mjs 는 `&debug` 없이는 `__aquaDebug` 가 없어 전부 타임아웃 — 1차 캡처 배치를 통째로 날렸다.
9. 성능(`stepg9`): 첫 계측 draws 106(밤 시각 — 별·후광 +3 포함) 이라 사람 둘을 **한 메시**로 합침(aPart 에 사람 오프셋 ×6, `uRot[12]` + 사람별 `uBody[2]` mat4 — 안 보이면 0 배율) → +6 (사람 1 + 보트 1 + 그림자 1, 두 패스).
